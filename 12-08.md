### Задание 1. Резервное копирование

### Кейс
Финансовая компания решила увеличить надёжность работы баз данных и их резервного копирования. 

Необходимо описать, какие варианты резервного копирования подходят в случаях: 

1.1. Необходимо восстанавливать данные в полном объёме за предыдущий день.

1.2. Необходимо восстанавливать данные за час до предполагаемой поломки.

1.3.* Возможен ли кейс, когда при поломке базы происходило моментальное переключение на работающую или починенную базу данных.

*Приведите ответ в свободной форме.*


###  Решение 1.

1.1. Необходимо восстанавливать данные в полном объёме за предыдущий день.

Подойдёт полный бэкап.
Если делается полный бэкап раз в сутки, то такой восстановление из полного будет предпочтительнее так же есть зависимость от объёма БД, возможно если база большая скорее всего будет восстановление с использованием дифференциального.

1.2. Необходимо восстанавливать данные за час до предполагаемой поломки.

Тут нам скорее всего подойдёт дифференциальный (т.к. полный бэкап делит сутки или более длинный период) условно делать повторно полный будет ресурсно затратно[или вообще нету возможности т.к. база упала] а если будет настроен дифференциальный раз в пол часа или раз в 15 минут, зависит от внутренних процессов.

1.3. Возможен ли кейс, когда при поломке базы происходило моментальное переключение на работающую или починенную базу данных.

Наверно да, если есть допустим виртуальная машина или реплика и работает что-то похожее на один из методов резервирования как "keepalived" и когда отвалится основной сервер, то резервный его просто заменяет.

### Задание 2. PostgreSQL

2.1. С помощью официальной документации приведите пример команды резервирования данных и восстановления БД (pgdump/pgrestore).

2.1.* Возможно ли автоматизировать этот процесс? Если да, то как?

---

### Решение 2.

Данная команда позволяет сделать дамп БД в кастом формате для восстановления утилитой pg_restore
 - **pg_dump -U myuser -d mydatabase -F c -f /tmp/mydatabase_backup.dump -v**

Данная команада восстанавливает данные в существующую БД, используя ключ -с предварительно очищаем.
 - **pg_restore -U myuser -d mydatabase_new -F c -c -v /tmp/mydatabase_backup.dump**
 
 '*'	Автоматизировать процесс восстановления БД из дампа возможно путём написания скрипта используя 'bash'. В скрипт можно добавить логику на проверку формата дампа.

### Задание 3. MySQL

3.1. С помощью официальной документации приведите пример команды инкрементного резервного копирования базы данных MySQL. 

3.1.* В каких случаях использование реплики будет давать преимущество по сравнению с обычным резервным копированием?

### Решение 3.

Для инкрементного резервного копирования MySQL рекомендуется использовать утилиту mysqlbinlog для работы с бинарными логами.

Далее необходимо предварительно редактировать конфигурационный файл my.cnf
Пример содержания файла:
 - [mysql]
	log-bin= /var/log/mysql/mysql-bin.log
	expire_logs_days = 7
	max_binlog_size = 100m

 '*' 
Репликация - это не только возможность вернуть утраченные данные в случае аварий или чрезвычайной ситуации, а ещё инструмент который можно использовать для повышения производительности, отказоустойчивости и работы с данными в реальном времени.
Наличие реплики даёт нам следующие преимущества
 - *1. Высокая доступность и отказоустойчивость ( если основной сервер упал, можно перенаправить трафик приложений на реплику)
 - *2. Масштабирование чтения (распределение запросов на чтение между серверами)
 - *3. Выполнение задач без водействия на основную базу.
 - *4. Географическое распределение.
 - *5. Аналитика и работа с данными - выполнение сложных запросов не помешает работе основной базы.

Репликация не выполнит задачу резервного копирования и обратно, одно другим заменить нельзя.
Необходимо использовать их для дополнения друг друга и выполнения одной задачи - поддержание работы системы.
